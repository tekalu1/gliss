# SVP・歌詞付き MIDI の取り込み

## 入力形式と抽出する情報

- SVP は JSON の `time.tempo`（位置は blick）、`time.meter`、`tracks[].mainGroup` と `library` のグループ参照を読む。1 四分音符 = 705,600,000 blick。グループ内ノートの `onset + blickOffset` を曲全体の位置にし、`pitchOffset` を音高に足す。ミュートしたグループ・ノートは除く。
- Standard MIDI File の format 0/1、PPQ を読む。テンポ・拍子のメタイベント、歌詞（0x05。テキスト 0x01 も受ける）、ノートの on/off を同じ `{start_sec,end_sec,pitch,lyric}` にする。UTF-8 と CP932 の歌詞に対応する。歌詞のない MIDI トラックは取り込めない。
- どちらも途中のテンポ変更を積分して秒へ変換する。SVP の `startTimeSeconds` も曲時刻へ加える。複数の歌詞付きトラックがあれば番号または名前で選ぶ。画面では選択ダイアログを出す。

## 時刻の変換と録音への対応付け

1. 譜面のノートを曲上の秒にし、録音 WAV の `bext.TimeReference / sample_rate` を引いてファイル上の位置に置く。切り出しクリップではソース上の開始秒も足す。`bext` が無ければ 0 秒と仮定し、その旨を返す。`song_start_sec` でファイル頭の曲時刻を明示することもできる。
2. 録音で測った有声音符と譜面の音高列を、bext の位置から ±8 秒で照合する。音高クラスが 1.5 半音以内の割合が 65% 以上、譜面に覆われる割合が 65% 以上、かつ bext の位置より一致率が 18 ポイント以上良い場合だけ開始位置を直す。補正したことと両方の一致率を返す。候補が弱ければ bext の位置を保持し、警告する。
3. 譜面のフレーズと録音の発声区間を、`list_utterances` と同じ `utterance_ranges`（音符間の隙間 300 ms 以下を結合し、前後に 120 ms の余白）で作る。譜面の各フレーズを最も重なる録音の発声区間に対応付け、その区間内の有声音符・発音の頭だけを照合する。譜面の歌詞付き音符の頭と録音の頭を ±180 ms で組み、差の中央値をフレーズごとに足す。少なくとも 2 組の頭・2 音符の音高一致・音高一致率 80%・残差中央値 90 ms 以下がそろわなければ保留にする。
4. 候補の歌詞区間は重ねずに `set_lyrics(entries=…)` で全件置き換える。推定歌詞と重なる場合も `origin: confirmed` の確定歌詞にし、元の推定値は比較用に残す。`undo` で戻せる。対応できない部分は `unmatched` に曲時刻と理由を返し、推測で割り当てない。

この照合は譜面と同じメロディーを歌った録音を前提にする。譜面から大幅に変えた歌唱、ラップや音高のない声、8 秒を超える位置の違いは保留または手動の `song_start_sec` を要する。

## 実ファイルでの検証と精度

2026-09-26 に、手元の曲の `vo.svp` とテイク・ガイドの録音（どちらも約 165 秒）を**読み取りのみ**で検証した。曲名・ファイル名・歌詞本文はここに記録しない。

| 対象 | bext の曲上開始 | 譜面・音高からの開始 | 照合結果 |
|---|---:|---:|---|
| テイク（164.779 秒） | 0.0000 秒 | **4.9350 秒** | bext のままなら音高一致 29%、補正後 74%（有声ノートの 89% が譜面内） |
| ガイド（164.794 秒） | **4.9315 秒** | 4.9315 秒を維持 | 補正したテイクとの差は 3.5 ms |

テイクの bext は録音内容の譜面上の開始位置を示していない。0 秒のままでは別のフレーズの歌詞が割り当たりうる。ガイドの bext と音高列は約 4.93 秒で一致するため、テイクの自動検算が必要だった。

2026-09-26 に `origin/main`（#48、`ff674e0`）を merge した後、同じファイルを `dry_run` で再測定した。テイクの `list_utterances` 相当の発声区間は 3 個で、対応した SVP フレーズは **7 区間**、保留は **23 区間**。7 区間はファイル上の 40.7249〜45.3482、45.6443〜52.0142、52.6154〜54.5161、122.0825〜126.2948、126.6135〜127.9842、128.6638〜130.7186、131.1113〜133.9880 秒で、元の 4 つの歌唱範囲を同じ発声区間の区切りで細分化したもの。ガイドは **17 区間**が候補、**13 区間**が保留。保留の主因はその曲位置で録音に発声がないこと。テイクの発音の頭の補正は各区間で +16.1〜+43.4 ms、残差中央値は 1.0〜28.7 ms だった。

精度の別検算として、取り込み側の superflux とは独立の **3 帯域の対数エネルギー差**（`engine/tests/onsets_ref.py` の `detect_onsets_energy`）で録音から頭を拾った。補正後の譜面の歌詞付き音符の頭から ±120 ms にあるエネルギーの頭を組むと、テイクは **84 組、絶対差中央値 24.8 ms・90 パーセンタイル 50.9 ms**、ガイドは **219 組、中央値 22.4 ms・90 パーセンタイル 62.6 ms**。これは近傍に頭を見つけた組の時刻誤差で、音素境界の精度や保留区間を含む全音符の正解率ではない。

## 歌詞の登録と対応できない区間

`import_lyrics` の `matched` は、譜面上の開始・テイク上の区間・対応した `list_utterances` の番号、時刻と `note_ids`・音符数・発音の頭の組数・補正量・残差・音高の一致数を返す。`unmatched` は譜面上の区間と「対応する発声がない」「歌詞または音符が不足」「発音の頭と音高の対応が不足」の理由を返す。`dry_run=true` で登録前に両方を確認できる。保留を直したい場合は、譜面・録音のトラックと時刻を確認してから `song_start_sec` を指定し、再度 `dry_run` する。統合テストでは推定歌詞を SVP の歌詞で上書きし、`get_lyrics().entries[].origin` が `confirmed` になることを確認した。

## MCP・画面での操作

```text
inspect_lyrics_score(path="…/vo.svp")
import_lyrics(path="…/vo.svp", dry_run=true)
import_lyrics(path="…/vo.svp")
import_lyrics(path="…/vo-exp.mid", track=1)
```

実ファイルの `vo.mid` は歌詞を持たない。同じ曲の別の 2 つの MIDI は複数の歌詞付きトラックを持つため、`track` が要る。画面では録音を開き、**ファイル > 歌詞を読み込む（SVP / MIDI）…** から譜面を選ぶ。複数トラックなら続いて選択する。ステータス行に読み込んだ区間と保留件数を出す。既存のテキスト読み込みも残る。

## 音声なしのガイドとして使う見通し

SVP/MIDI の音高・長さ・テンポからガイドノートと歌詞の目安は作れる。今回のテイクでは譜面と音高が 74% 一致し、曲上の原点も 3.5 ms まで確認できたので、音声ガイドがない場合でもノートの目標位置を示す用途は見込める。ただし譜面のノート頭と実際の発音の頭には数十 ms の差があり、装飾・しゃくり・休符内の子音はノートだけでは表せない。現行の「ガイドに合わせる」は音声の発音の頭・F0 と DTW を使うので、そのまま譜面に差し替えると同じ精度は保証できない。譜面専用のノート対応と、信頼度が低い頭を動かさない判断、音高の連続カーブへの変換を別途設計する。今回の実装は歌詞取り込みまで。
